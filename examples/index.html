02 / Continuous integration

Small changes.
Fast feedback.

From a local commit to a shared signal of confidence.

A system, at a glance

Every change gets a safety net

The fast path

Run cheap, deterministic checks first. Return useful feedback while the change is still fresh.

The human boundary

Automation supplies evidence. Reviewers still evaluate intent, risk, and tradeoffs.

A pipeline you can explain

pipeline:
  name: verify-change
  steps:
    - name: install
      run: pip install -r requirements.txt
    - name: test
      run: pytest --maxfail=1
    - name: lint
      run: ruff check .

Predict before running

What happens if a test fails?

Which step should never run after that failure?

Illustrative YAML, not a vendor-specific pipeline schema.

Would you merge this change?

The pipeline is green. The change disables a slow integration test.

  1. What evidence is missing?
  2. Who takes on the risk?
  3. What would make the change safe enough to merge?

Take 30 seconds to think. Then compare your reasoning with a partner.

A green build is not the whole story

  • Check why the test is slow and what behavior it protects.
  • Replace lost coverage or make the risk explicit and time-bounded.
  • Agree on an owner and a follow-up before removing the safety net.
Teaching tip

Resolve the reasoning, not just the answer. Different contexts can justify different decisions.

Reference / Quiet, readable detail

Choose the right feedback loop

Typical checks, ordered from narrow to broad
CheckQuestion it answersWhen to run
Unit testDoes this small piece behave correctly?Every change
Integration testDo the real components work together?Before merge
End-to-end testCan a user complete a critical journey?Selected workflows
Watch the boundary

More tests do not automatically mean more confidence. Reliability and relevance matter.

Which check gives the fastest feedback?

A. A unit test   B. A full deployment   C. A manual acceptance review

Type A, B, or C in chat. You may also keep a private answer or pass.

Start with the narrowest useful check

A. A unit test usually gives the quickest signal for a small behavior.

It complements integration testing; it does not replace it.

Look for the cost of waiting

  • A defect discovered after release.
  • A review blocked by missing context.
  • An environment mismatch found at deployment time.
